# 输入输出规范

## 一、输入

### 1.1 用户输入的时间范围（三种，只认这三种）

| 形式 | 示例 | 起始 | 结束 |
|---|---|---|---|
| `YYYY-MM-DD` 到 `YYYY-MM-DD` | `2022-01-01 到 2025-12-31` | `2022-01-01` | `2025-12-31` |
| `YYYY-MM` | `2024-03` | `2024-03-01` | `2024-03-31` |
| `最近N天` | `最近30天` | 今天往前推 `N-1` 天 | 今天（含） |

**边界日期一律包含**（闭区间）。

**无法解析的处理**：立即停止，原样输出以下提示，不得推断、不得取整、不得默认成"全部"：

```
无法识别你输入的时间范围：<原文>
请按以下任一格式重新提供：
  1) 2022-01-01 到 2025-12-31
  2) 2024-03
  3) 最近30天
```

### 1.2 页面上的时间文本（程序会自动解析）

| 形式 | 例子 |
|---|---|
| 绝对日期 | `2022-03-05`、`2022/3/5 12:30`、`2022年3月5日`、`2022.03.05` |
| 相对时间 | `3天前`、`2小时前`、`昨天 18:20`、`刚刚` |

相对时间按系统当天日期倒推后再比较。

**日期无法解析的条目**：一律视为不在范围内，跳过并单独列出（见输出清单的「无法解析」段），不得当作范围内删除。

### 1.3 配置文件（config.yaml）

复制 `config.example.yaml` 为 `config.yaml` 后修改。所有键都有默认值，缺项不会报错。

**你大概率要改的**：

```yaml
range:
  start: "2022-01-01"
  end: "2025-12-31"
```

**你可能要改的**：

```yaml
limits:
  min_delay: 1.25        # 两条之间的最小间隔（秒）
  max_delay: 3.75        # 最大间隔
  daily_max: 0           # 单日上限，0=不限
  cooldown_seconds: 0    # 失败后等待秒数，0=不等待
restriction:
  cooldown_seconds: 0    # 限流后等待秒数，0=不等待
  max_retries: 5         # 最多重试 5 次（立即探测）
```

完整键见 `config.example.yaml` 内的注释。

## 二、输出

### 2.1 待删清单（dry-run 阶段生成）

路径：`logs/dryrun-<时间戳>.csv`

```csv
序号,发布日期,是否在范围,标题,时间原文,key
1,2022-04-03,是,#创业 千万次的努力...，2022年04月03日 17:30,a1b2c3d4e5f6
2,2022-04-09,是,为何涨工资不如扣工资？...,2022年04月09日 20:30,9f8e7d6c5b4a
```

**范围内**的条目需要用户确认后才执行删除；**范围外**和**无法解析**的条目只列出，不处理。

### 2.2 实时进度（运行中）

路径：`logs/daemon-status.json`（守护模式）

```json
{
  "round": 1,
  "pending": 2661,
  "total_deleted": 1128,
  "state": "running",
  "updated": "2026-10-27 16:44:26"
}
```

### 2.3 操作日志

| 文件 | 内容 |
|---|---|
| `logs/run-<runid>.log` | 人类可读，每步一行，含时间戳 |
| `logs/ops.jsonl` | 结构化，一行一个 JSON，字段含 `action / phase / title / how / detail` |
| `logs/restrictions.jsonl` | 限流记录（发生时才生成） |
| `logs/RESTRICTION-REPORT.md` | 限流报告（发生时才生成） |
| `state.json` | 断点状态 |

### 2.4 完成报告（程序输出的最后总结）

```
============================================================
  扫描 2752 条 / 命中范围 2677 条 | 列表删除 2677 | 失败 0 | 跳过 0 | 用时 3h42m
============================================================
```

若仍有失败/跳过条目，需附：标题、时间、失败原因。

### 2.5 截图

- 失败时：`shots/<runid>/NNNN_<原因>.png` + `index.jsonl`
- 运行结束默认**清空** `shots/`（对应需求"运行完毕后删除所有截图"），清单信息留在日志里。
- 想留证据：加 `--keep-shots`，或把 `app.purge_shots_on_finish` 改为 `false`。
